# ADR-006 — xxHash64 State Hashing + Serialization Notes

## Status

PARTIAL (wrapper READY y probado; corte del hash de snapshot PLANNED;
MessagePack/LZ4 OPEN tras benchmark — ver OPEN-006).

## Context

El brief pide sustituir CRC32 por `System.IO.Hashing.XxHash64` (no hash
criptográfico), cubrir CADA BYTE del snapshot en orden de declaración,
documentar el orden, crear `DeterminismProbe` con excepción tipificada, y
serializar con MessagePack (+LZ4 en replays) con benchmark <0.4 ms en
Android ARM64 gama media. Realidad 2026-09-14:
(1) el repo usa FNV-1a, no CRC32 (el brief asume CRC32 — ver DF-CON-006);
(2) `System.IO.Hashing` NO viene in-box para este proyecto: requiere
`PackageReference` (fijado 9.0.0, restaurado de nuget.org 2026-09-14);
(3) OPEN-006 difiere MessagePack/LZ4 hasta tener benchmark (layout manual LE
vigente, medido); ReplayV2 guarda SIN comprimir (flag 0, upgrade reservado).

## Decision

1. **`DeterminismHash`** (`src/Fighter.Core/DeterminismHash.cs`): wrapper
   xxHash64 (seed 0 + seed explícita para separación de dominios). Paquete
   `System.IO.Hashing 9.0.0` fijado: managed puro, sin nativos, apto
   x64/ARM64 incl. Android/iOS, AOT/IL2CPP-safe. Justificación del paquete
   en Core (cero paquetes antes): BCL oficial, sin plataforma específica.
2. **Evidencia** (2026-09-14): vector canónico vacío `0xef46db3751d8e999`;
   vector oficial "abc" `0x44BC2CF5AD770999`; rampa 512B pineada por
   ejecución `0x7B3BFCAAC0348AC0` (un valor previo no ejecutado fue
   corregido); sensibilidad a orden/último byte; semillas separan dominios.
3. **El hash de snapshot NO cambia todavía** (FNV-1a vigente): el corte
   (hashear cada byte en orden de layout vía este wrapper + regen de
   goldens) es PLANNED explícito. `DeterminismProbe`
   (`RecordFrame`/`Assert` → `DeterminismViolationException` con
   frame/expected/actual) existe y está probado; el hash de diagnóstico es
   independiente de integridad de replay, seguridad y red.
4. **ReplayV2 (.fr2p)**: magic `DF 00 01`, format u16, game version UTF-8
   16B, RNG 4×u64, stage/p1/p2/platform u8, flag compresión (0 = none),
   snapshot inicial full + frames 8B empaquetados, footer xxHash64. Fallos
   tipificados (`ReplayCorruptException`): magia, versión, schema, longitudes,
   truncado, footer, plataforma/ids. Sin LZ4 aún (paquete + vetting IL2CPP
   pendientes); sin MessagePack (OPEN-006: benchmark manda).
5. **Benchmark**: micro-bench existente (Stopwatch, 10k iters, dev host).
   BenchmarkDotNet NO añadido (paquete nuevo + restore; el bench actual
   guarda contra regresión gruesa <2 ms). Android real: sin dispositivo en
   esta sesión (D4 cubre paridad por harness, no timings).

## Consequences

- Hash moderno disponible sin romper goldens ni replays.
- Replay v2 con integridad punta a punta (adversarial probado: 1 byte → throw).
- Compresión/serialización binaria siguen OPEN con criterio medible.

## Alternatives considered

- Corte inmediato FNV→xxHash en snapshots: REJECTED hoy (regen de goldens
  sin decisión formal).
- xxHash3 / hash criptográfico: REJECTED (xxHash64 basta para divergencia;
  cripto no sustituye hash de sim).
