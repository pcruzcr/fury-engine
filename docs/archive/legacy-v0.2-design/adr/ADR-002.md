# ADR-002 — F1 combat model (data-driven, integer-only)

Date: 2026-09-13 · Status: ACCEPTED · Owner: Principal Software Architect
Depends: ADR-001 · Resolves: OPEN-001..005 (see 10-open-decisions.md; decision source: user/Game Director)

## Context
F1 must implement FSM, CommandNormalResolver, AABB, hit detection, combat resolution, damage,
hitstop, defense, energy, Rage, Resonance and Glen on the F0 substrate — without inventing
behavior where the spec is silent, and without scattering magic numbers.

## Decision
1. **Data-driven moves.** Every number lives in `GlenData` (GDD v8.0 §3.2 values where specified).
   Gaps the GDD does not specify (active frames, recovery, walk/jump physics, pushback, stun
   durations, parry/backdash windows) live in ONE centralized `Calibration` class, each marked
   `[CAL]` = F1 calibration pending the feel pass. `DataValidator` rejects inconsistent data
   (bad ordering, duplicates, non-positive frames, negative damage) loudly at load.
2. **Blockstun formula (no invented table):** `blockstun = attackerFramesRemaining + onBlock`
   (min 1). Produces exactly the specified onBlock advantage with both counting down together.
3. **Hitstun:** Light 7f / Medium 12f / Heavy → Knockdown (19f stun → 30f down → 8f wakeup).
   Midpoints of the GDD §4.4 ranges, centralized in `Calibration`.
4. **Juggle:** airborne victim in hitstun may be re-hit; `JuggleCount` caps at character
   `JuggleMax` (Glen = 3, character data, not Core magic); at cap → knockdown.
5. **Throws:** proximity + inblockable; victim LP+LK edge within last 10f (ring history) → tech,
   both neutral + separation. No invented windows: 10f comes from GDD §4.6.
6. **Parry:** edge tap-down in neutral → stance 6f (10f Dant Rage); whiff-recovery 12f [CAL]
   during which a hit deals ×6/5 (the specified fail case). OPEN-004 grace = 2f [CAL], first
   Dant-Rage attempt only. Success: attacker ParryStun 15f, defender +15% EX / +10% RES.
7. **Energy:** all §28/§29 rules with resolved OPENs; Rage auto-fires at 3000 EX (consumes all);
   manual Burst excluded (MVP scope). Resonance manual activation allowed when cooldown ready
   and round use unconsumed (F1 rule, flagged for Systems review — GDD is silent on the input).
8. **Snapshot v2** (schema 2, now +`SuppressJump`) carries every §33 field now simulated;
   v1 payloads rejected loudly. F0 `DeterministicSim` untouched — substrate tests stay green.

## Amendment F1-impl (2026-09-13, during implementation — all explicit, tested)
- **Cancel gate:** StartActions admits Attack+DidHit (without it resolver cancel legality is dead code).
- **Gated-motion sentinel:** meterless super returns −1 (edge consumed, NO fallback to QCF/buttons).
- **Input priority:** motion-gated specials (`MotionGated` data flag) eat same-frame up-inputs
  (`SuppressJump`, snapshot-covered); a lone U still jumps.
- **Backdash double-tap** requires the first tap to originate from neutral stick (disambiguates
  block-hold resumes; cost: no instant backdash out of forward walk). Feel-review flagged.
- **Counter stances** never count as active strikes (`IsActive` excludes them).
- **Throws** skip the strike hitbox (own `ThrowRange` check); **no air throws** (F1 rule).
- **Hitstop eats inputs** (histories not even pushed while frozen — standard freeze behavior);
  tests tap chains only after the freeze. No air normals yet (Kira/juggle pass).
- **Validator fix:** motion-gated specials/supers/command-grabs may carry `Buttons.None`.

## Consequences
- Balance changes = data edits, never Core architecture changes (§92).
- `[CAL]` constants are the explicit agenda of the feel pass; none is hidden in logic.
- Projectile-vs-projectile: NOT IMPLEMENTED (no F1 fighter has projectiles) — no dead code.
