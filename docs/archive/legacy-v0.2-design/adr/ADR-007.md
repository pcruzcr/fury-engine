# ADR-007 — AOT/IL2CPP Compatibility

## Status

READY (auditoría ejecutada 2026-09-14; ejecución móvil pendiente de hardware).
BLOCKING: YES (solo ejecución en dispositivo, no configuración).

## Context

Targets: Windows x64, Linux x64, Android ARM64/x86_64, iOS ARM64, macOS
ARM64/x64. Todo tipo de Core debe ser compatible AOT/IL2CPP. Prohibidos:
`Type.GetType(string)`, `dynamic`, `Reflection.Emit`, DLR. Reflection con
justificación + alcance + alternativa estática. Constraints genéricas
explícitas cuando aplique.

## Decision

1. **Auditoría ejecutada 2026-09-14** (grep sobre `src/Fighter.Core`):
   cero `float`/`double` en estado; cero `Math.Sin/Cos`, `MathF.*`;
   cero `System.Random`/`Guid`/`TickCount` en sim; cero referencias
   `Godot`/`System.Numerics` en lógica (solo comentarios que los prohíben);
   cero `dynamic`/`Reflection`/`Emit`/`GetType(string)` en Core. (La
   reflexión vive SOLO en tests: `CorePurityTests`, guard de pureza, no
   en producto.)
2. **Reglas aplicadas al código nuevo de la sesión**: `GimmickData` =
   struct explicit-layout blittable sin referencias; `IInputProvider` =
   interfaz plana sin miembros default ni genéricos; `RingBuffer<T>.CopyTo`
   usa `Span<T>` (sin unsafe; `unsafe` queda prohibido salvo ADR futuro);
   `SimulationLoopEnforcer`/`SingleThreadGuard` = `[Conditional("DEBUG")]`
   (cero costo RELEASE); `System.IO.Hashing` = managed puro (ver ADR-006);
   genéricas nuevas (`RingBuffer<T>`) sin constraints ocultas.
3. **Excepciones tipificadas** derivan de `InvalidOperationException`
   (sin serialización binaria legacy: compatible con trimming/AOT).
4. **Ejecución móvil**: SIN EVIDENCIA en esta sesión (sin dispositivos,
   sin plantillas de export instaladas). `Fighter.DeterminismHarness` es el
   vehículo documentado (procedimiento adb/ writcup en
   `docs/dev-plan/exports.md` — PENDIENTE de redactar, ver OPEN-010).
   Sin afirmación "iOS verified": solo compile target.

## Consequences

- Core es técnicamente AOT/IL2CPP-safe por construcción + auditoría.
- La matriz móvil queda READY (config) / pendiente (ejecución humana).

## Alternatives considered

- `unsafe` + punteros en RingBuffer/snapshot: REJECTED (Span cubre el
  hot path sin vetting extra).
- Comentarios ceremoniales de compatibilidad por archivo: REJECTED
  (la compatibilidad se verifica, no se proclama).
