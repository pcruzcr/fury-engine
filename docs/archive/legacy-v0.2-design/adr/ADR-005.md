# ADR-005 — RNG Algorithm (xoshiro256** READY, cutover pending)

## Status

READY (implementado y probado; el sim vivo aún usa SplitMix64 — ver corte).
BLOCKING: YES (el corte requiere regen de goldens + decisión Lead Programmer).

NOTE ON NUMBERING: el brief pide "ADR-003 — RNG", pero ADR-003
(`Godot presentation`) ya existe. Continúa en ADR-005. Ver DF-CON-006.

## Context

El brief exige xoshiro256** con estado ulong[4], seed reproducible, Jump y
LongJump; el estado RNG participa en snapshot/hash/replay/rollback; tests de
reproducibilidad, 10k draws + hash cruzado, chi-square, Jump/LongJump,
ausencia de estado implícito; no confundir seed inicial con estado actual.
Realidad 2026-09-14: `DeterministicRng` (SplitMix64, 1×ulong) alimenta
`FightSimulation` y `DeterministicSim`; todos los certificados/goldens
dependen de ese stream. Cambiar el stream en caliente invalidaría
silenciosamente cada hash pinneado.

## Decision

1. **Nuevo tipo `Xoshiro256StarStar`** (`src/Fighter.Core/Xoshiro256StarStar.cs`):
   transición y polinomios JUMP/LONG_JUMP copiados verbatim de la referencia
   oficial https://prng.di.unimi.it/xoshiro256starstar.c (verificada
   2026-09-14; el 4º word de JUMP difiere del recuerdo común — por eso se
   verificó contra fuente). `FromSeed` vía SplitMix64 (expansor de seed
   sugerido por los autores, no stream de sim). `CopyStateTo(Span)` /
   `RestoreState` para snapshot. Estado todo-cero rechazado.
2. **El sim vivo NO cambia todavía.** `DeterministicRng` sigue alimentando la
   simulación. El corte (sim → xoshiro, snapshot del estado 4×ulong, regen
   de `golden_hashes.json` + certificados) es una tarea PLANNED explícita,
   no un cambio silencioso.
3. **Evidencia del algoritmo** (tests 2026-09-14): vectores verificados a mano
   contra la fórmula de referencia (estado 1,2,3,4 → 11520, luego 0);
   reproducibilidad; 10k draws distintos; round-trip de estado; Jump/LongJump
   deterministas y divergentes; `NextUInt` = mitad alta; `NextBounded` con
   rechazo; chi-square uniforme (low-byte, 65536 draws, <400); hash cruzado
   10k pineado `0x9F8459407027DBF9`; sin estado implícito (instancias
   independientes).
4. **ReplayV2 reserva** words1-3 del estado RNG a cero para el corte
   (documentado en `ReplayV2.cs`): el formato no se rompe al migrar.

## Consequences

- Algoritmo conforme a referencia, listo para adopción sin rediseño.
- Hasta el corte, `DeterminismHash`/goldens siguen estables (cero deriva).
- Seed inicial ≠ estado actual: el snapshot futuro guardará las 4 words
  vivas, no la seed.

## Alternatives considered

- Corte inmediato sim→xoshiro: REJECTED hoy (invalida goldens sin decisión
  formal; viola "no silent schema changes").
- Mantener SplitMix64 para siempre: OPEN (xoshiro aporta substreams
  Jump/LongJump para rollback paralelo futuro; decisión del corte pendiente).
